<task type="auto">
  <name>Task 2: Implement DemoLogbookRepository (demo + Prisma paths)</name>
  <files>src/modules/logbook/repository.ts</files>
  <action>
Implement `class DemoLogbookRepository implements ILogbookRepository` and `export const logbookRepository: ILogbookRepository = new DemoLogbookRepository();` (mirrors `individualTaxRepository` singleton export).

**Demo path (every method: `if (isDemoMode) { ... }`):** read array → find/mutate → write array → return clone. Rules:
- IDs: `crypto.randomUUID()` (import `node:crypto` `randomUUID`) for every new logbook, vehicle, and trip id. NEVER copy the `Date.now() + Math.random()` pattern from individual-tax/repository.ts lines 266/372 — PITFALLS.md flags it as collision-prone for audit-facing records.
- `createLogbook`: pre-check `getLogbookByClientAndYear`-style duplicate — reject (throw `Error("A logbook already exists for this client, vehicle and tax year.")`) when a record with the same `clientId`, `assessmentYear`, and `vehicle.registrationNumber` (case-insensitive trim compare) exists. Set `costMethod: "DEEMED"` default, `actualExpenses: null`, `trips: []`, ISO timestamps via `new Date().toISOString()`.
- Trip mutators: locate record by id (throw `Error("Logbook not found.")` if absent), locate trip by id for update/delete (throw `Error("Trip not found.")`), set `updatedAt` on both trip and record. In test mode the array mutation itself is the persistence (writes are no-ops) — mutate the found record in place, then return a clone.

**Prisma path (the `else` branch):** use the plan 02-01 models:
- `createLogbook`: `prisma.vehicle.create` then `prisma.logbook.create` (or nested create), relying on `@@unique([clientId, vehicleId, assessmentYear])` for the DB-level guarantee.
- Reads: `prisma.logbook.findFirst/findMany` with `include: { vehicle: true, trips: { orderBy: { date: "asc" } } }`.
- Map rows → `LogbookRecord` in a private `mapRow` (Decimal → `Number(...)`, DateTime → `toISOString().slice(0, 10)` for trip `date`, full ISO for timestamps) — same conversion style as `DemoIndividualTaxRepository.mapRow`.
- Trip mutators: `prisma.logbookTrip.create/update/delete` then re-read the logbook via the include query and return the mapped record.

No audit logging here — that is the service layer's job (plan 02-04), matching the existing layering.
