SheetJS facts (from research):
- `XLSX.read(arrayBuffer, { type: "array", cellDates: true })` converts date-formatted cells to JS Date objects; cells stored as plain numbers (not date-formatted) legitimately stay numeric.
- `XLSX.utils.sheet_to_json<Record<string, unknown>>(sheet, { defval: "" })` yields row objects keyed by the header row, `defval` filling empty cells.
- Fixtures can be generated programmatically: `XLSX.utils.aoa_to_sheet([...])` + `XLSX.utils.book_new()` + `XLSX.write(wb, { type: "array", bookType: "xlsx", cellDates: true })` — no binary files committed to the repo (research Open Question 3 recommendation).

Create `src/modules/logbook/import/parse-xlsx.ts`:

```typescript
export function parseXlsxArrayBuffer(buffer: ArrayBuffer): ParsedImportData;
```

Implementation:
1. `XLSX.read(buffer, { type: "array", cellDates: true })`; take the FIRST sheet (`workbook.SheetNames[0]`). Empty workbook / no sheets -> return empty ParsedImportData with one error entry `{ row: -1, message: "Workbook contains no sheets." }` (no throw — errors are data in this pipeline).
2. `XLSX.utils.sheet_to_json<Record<string, unknown>>(sheet, { defval: "" })` for rows; headers from the keys of `sheet_to_json(sheet, { header: 1 })`'s first row (trimmed, stringified) so the header list is exact even when all data cells in a column are empty.
3. Normalize EVERY cell value to string via a `normalizeCell(value: unknown): string` helper:
   - `Date` instance -> ISO date string `YYYY-MM-DD`. Derive the date parts so the round-trip fixture test in Task 2 passes: start with UTC getters (`getUTCFullYear`/`getUTCMonth`/`getUTCDate`); if the fixture test shows off-by-one-day drift (SheetJS date construction is timezone-sensitive), switch to local getters — the fixture test is the arbiter, document which was needed in a comment.
   - number -> `String(value)` (raw serials survive as numeric strings; `normalizeDateCell` in column-mapping converts serial-range numerics later)
   - boolean -> "TRUE"/"FALSE"; null/undefined -> ""; string -> trimmed as-is
4. Return `{ headers, rows, errors: [] }` on success.

Keep this file free of React/DOM/worker imports — pure transform (research Pattern 1).

Create `src/modules/logbook/import/xlsx.worker.ts` — thin entry only, no logic:

```typescript
import { parseXlsxArrayBuffer } from "./parse-xlsx";

self.onmessage = (event: MessageEvent<ArrayBuffer>) => {
  try {
    self.postMessage({ ok: true, data: parseXlsxArrayBuffer(event.data) });
  } catch (error) {
    self.postMessage({ ok: false, error: error instanceof Error ? error.message : "Failed to parse workbook." });
  }
};
```

Export the message envelope type (`XlsxWorkerResponse`) from parse-xlsx.ts (or types.ts) so plan 04-06's orchestrator types its onmessage handler against it.

```typescript
function buildWorkbook(aoa: unknown[][], writeOpts: Partial<XLSX.WritingOptions> = {}): ArrayBuffer {
  const ws = XLSX.utils.aoa_to_sheet(aoa);
  const wb = XLSX.utils.book_new();
  XLSX.utils.book_append_sheet(wb, ws, "Logbook");
  return XLSX.write(wb, { type: "array", bookType: "xlsx", cellDates: true, ...writeOpts });
}
```

Test cases:
1. **SARS-layout with real Date cells:** aoa with headers `["Date", "*Opening Km", "*Closing Km", "Total Business Km", "From", "To", "Reason"]` and rows whose Date cells are actual `new Date(Date.UTC(2026, 2, 15))`-style JS Dates (aoa_to_sheet stores them as date cells). Assert the parsed row's Date cell is exactly `"2026-03-15"` — THE serial-date round-trip proof (IMP-02's core assertion). Use at least two dates in different months to catch day/month transposition.
2. **Raw serial number cell:** build a sheet where a date cell is written as the plain number 45658 (not a Date). Assert the parsed cell is the string `"45658"` AND that `normalizeDateCell("45658")` (imported from parse-dates) returns `"2025-01-01"` — proving the two-stage path for unformatted serials.
3. **Text date cell:** a Date column cell holding the literal string "15/03/2026" survives as that string (conversion downstream).
4. **Empty cells:** a row with blank From/To arrives with `""` values (defval), keys present.
5. **Mixed types:** numeric business-km cell -> `"123.5"` string; boolean -> "TRUE"/"FALSE".
6. **Empty workbook:** `parseXlsxArrayBuffer` of a workbook with an empty sheet returns empty rows without throwing; a completely sheetless input (construct via `XLSX.write` of an empty book_new if writable, else pass a corrupt-ish buffer inside try) surfaces the error entry rather than throwing.
