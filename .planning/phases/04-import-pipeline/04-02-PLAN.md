<task type="auto">
  <name>Task 2: importTripsToLogbook service function with single audit entry</name>
  <files>src/modules/logbook/service.ts</files>
  <action>
Add to `src/modules/logbook/service.ts`:

```typescript
export async function importTripsToLogbook(
  logbookId: string,
  trips: unknown,
  source: "CSV" | "XLSX" = "CSV",
): Promise<LogbookRecord>;
```

Implementation, mirroring `addTripToLogbook`'s structure:
1. Parse input with `z.array(tripInputSchema).min(1)` — a batch with ANY structurally invalid trip throws before anything is loaded or written (atomic reject; the import preview in plan 04-06 is responsible for filtering invalid rows out BEFORE calling this, so reaching here with bad data is a programming error, not a UX path).
2. `loadLogbookOrThrow(logbookId)`.
3. Build `prospectiveTrips = [...record.trips.map(toContinuityTrip), ...parsedTrips.map(toContinuityTrip)]` and call the existing `assertOdometerContinuity({ openingOdometer: record.openingOdometer, closingOdometer: record.closingOdometer }, prospectiveTrips)` — the merged-set check, same gate as manual capture (Pitfall 4: import must never get a laxer validation bar than manual entry).
4. `logbookRepository.addTrips(logbookId, parsedTrips.map(...))` with nullish odometers normalized to null (same mapping as addTripToLogbook).
5. ONE `writeAuditLog` call:
   - action: `"LOGBOOK_TRIPS_IMPORTED"`
   - entityType: `"Logbook"`, entityId: logbookId
   - summary: `` `Imported ${parsedTrips.length} trips from ${source} import into the ${record.assessmentYear} logbook.` ``
   - afterData: `{ tripCount: parsedTrips.length, source }`
6. Return the updated record.

Import `z` from "zod" if not already imported in service.ts. Do not modify existing functions.
